01 The problem

Day one in a codebase you have never seen. Your options:

01 Stale docs written once, aging ever since.
02 A teammate’s whole day one expert, one day, one joiner at a time.
03 An unchecked chatbot fluent, confident, unverified.

Getting an explanation of code is easy now.
Trusting one is not.

02 What we built

your-repo/ ─────▶ trailhead.html

One repo in.
One file out.

A single self-contained HTML walkthrough that teaches the codebase to a new joiner, and shows its evidence for every claim it makes.

NO SERVER NO LOGIN NO INTERNET OPENS FROM file://

Scoped to Python, by choice. Depth over coverage.

03 How the checking works

Every sentence is a claim. Every claim is checked by ordinary code.

QUOTE
The model must return a verbatim excerpt with each claim.
→
RESOLVE
Plain code finds that excerpt in the file.
→
ANCHOR
file:line plus a content fingerprint.
→
RE-VERIFY
Every anchor is re-read after the prose is written.
DELETED Failed claims are deleted, not flagged.
inferred Unverifiable prose is visibly marked.
COUNTED ON SCREEN Deletions are tallied where the reader can see them.

Engineering note: never ask a model for line numbers. Models count badly; they copy well. Verbatim quotes, resolved to file:line in code, cut the claim drop rate from 40% to 3%.

05 Why it matters

What verification buys you

STALENESS

Docs that rot loudly

Anchors and fingerprints can be re-checked in CI. When the code moves, the walkthrough fails visibly instead of quietly going stale.

TRUST

Auditable AI

Every sentence carries its evidence and its verdict. A ledger, not a shrug.

FOOTPRINT

A file, not a service

Nothing to host, nothing to log into, nothing to maintain. Nothing leaves the building.

The model writes the prose. The machine checks the facts.

Every sentence shows its evidence, is marked as unverified, or is gone.
