
## SLAM Documentation

SLAM is a markup language used for documenting Slang code. When the user asks for help with **SLAM documentation** of a Slang file:

- Refer to `.github/SLAM/` folder for guidance and examples
- `slamExample` - Contains comprehensive examples of SLAM markup syntax
- `SLAMGuide` - Contains the SLAM documentation guide

## Critical Rules

### Spacing
All SLAM markup AND Comments in general must be exactly 2 spaces (or 1 tab) after `**` or `//`.
```
CORRECT:  **  === Heading ===
WRONG:    ** === Heading ===
```

### Heading Hierarchy
- `== Title ==` (level 1) - Module description only
- `=== Section ===` (level 2) - Must follow a level 1
- `~~ Local Heading ~~` - Use for routine/code block comments (no nesting rules)

### Escape Angle Brackets
Non-tag angle brackets cause lexing errors. Escape with backslash: `\<name\>` not `<name>` 

### Line size
none of the lines in the file should be over 150 characters, def not over 190!
